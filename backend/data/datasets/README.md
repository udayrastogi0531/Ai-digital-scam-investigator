# Training datasets

This directory holds **training data only**.  It is strictly separated from
the **evaluation corpus** (`../evaluation/evaluation_cases.json`), which
measures the whole pipeline and must **never** be used to train a model.

## What lives here

| Path | Purpose | Can be trained on? |
|---|---|---|
| `scam_messages.csv` | Synthetic/demo rows generated by `scripts/ml_training/generate_dataset.py` | Yes (demo only — metrics are not real-world evidence) |
| `real/` | Put vetted, permissioned real labelled data here | Yes (this is the intended real-data path) |
| `evaluation_report.json` | Honest metrics report written by `train.py` for the dataset it trained on | No (output artifact) |
| `../evaluation/` | Realistic end-to-end evaluation corpus (58+ fictional cases) | **Never** — enforced by the loader |

## Recommended real-dataset schema

CSV, JSON (list of objects or `{"rows": [...]}`) and JSON-lines are
supported.  `text` and `label` are required; all other columns are
validated when present.  `id`, when present, must not collide with an
evaluation-corpus id (contamination guard in `app/ml/dataset.py`).

| Column | Required | Values / format | Notes |
|---|---|---|---|
| `id` | no | stable string | used for duplicate + contamination detection |
| `text` | yes* | free text | the message content (*unless `urls` is set) |
| `urls` | no | JSON array string, or space/comma separated | URL(s) associated with the message |
| `label` | yes | `scam` \| `benign` | ground truth |
| `scam_category` | for scam rows | one of the rule-engine categories (see `app/patterns/rules.py`) | e.g. `phishing`, `job_scam`, `banking_scam` |
| `source` | no | e.g. `email`, `sms`, `social`, `internal_soc` | provenance |
| `language` | no | ISO 639-1, e.g. `en` | enables per-language evaluation |
| `timestamp` | no | ISO-8601 | when the message was seen/collected |
| `annotation_confidence` | no | 0..1 | human agreement for the label |
| `notes` | no | free text | ground-truth justification, anonymisation notes |

Example CSV row:

```csv
id,text,label,scam_category,source,language,timestamp,annotation_confidence,notes
rl-0001,"URGENT: verify your account at http://paypal-verify.example/login now",scam,phishing,email,en,2026-08-01T09:12:00Z,0.9,"lookalike domain; confirmed phish"
```

## Honesty policy

* **No fabricated real-world data.** Nothing in this repository pretends a
  synthetic set is real.  `train.py` prints a warning whenever it trains on
  the synthetic set and records `dataset_origin: synthetic` in its report.
* **No private/personal information in committed datasets.** Only
  fictional or permissioned/anonymised data may be committed here.
* **Validation is enforced, not advisory.** `load_dataset()` rejects rows
  with missing content, invalid labels, unknown categories, out-of-range
  annotation confidence, or duplicate ids/text — and reports dataset
  statistics before training.
* **Separation is enforced.** Loading anything under `../evaluation/` (or a
  row whose `id` matches an evaluation case) raises
  `DatasetValidationError`.

## Using a real dataset

1. Place the file under `real/` (e.g. `real/soc_2026_q1.csv`).
2. Train: `python scripts/ml_training/train.py --dataset data/datasets/real/soc_2026_q1.csv`
3. The script prints dataset statistics, a stratified train/val/test split
   and precision/recall/F1/confusion matrix for the *test* split, then
   saves the pipeline to `app/ml/models/lr_scam_model.joblib`.

See the module docstring in `app/ml/dataset.py` for the exact validation
rules and the schema contract used by the training scripts.
